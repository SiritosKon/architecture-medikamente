# Задание 3. Шифрование данных при хранении и передаче

## 1. Классификация данных и инструменты защиты

Под названием данных указаны класс, состояние и риск:
- **класс:** C1 — внутренние, C2 — конфиденциальные, C3 — персональные, C4 — особо чувствительные;
- **состояние:** хранение и/или передача;
- **риск:** критический, высокий, средний или низкий.

| Данные | В чём необходимость защиты | Инструменты защиты |
|---|---|---|
| **Диагнозы, анамнез, заключения**<br>C4 · хранение, передача · критический | Спецкатегория ПДн и врачебная тайна (152-ФЗ ст. 10, 323-ФЗ ст. 13); утечка — штрафы и потеря доверия | Шифрование диска и полей с ключом на пациента; доступ только лечащему врачу; TLS / mTLS |
| **Результаты анализов**<br>C4 · хранение, передача партнёру · критический | То же; передаются внешней лаборатории | mTLS + OAuth2, заказ без ФИО, шифрование полей |
| **Ключи и секреты**<br>C4 · хранение · критический | Компрометация открывает доступ ко всему | Vault + HSM, ротация ключей |
| **Паспорт, СНИЛС, полис**<br>C4 · хранение · высокий | Кража личности, мошенничество | Токен вместо значения, сканы не хранятся |
| **Запись к специалисту, услуги в счёте**<br>C4 (косвенно) · хранение, передача · высокий | По ним можно понять диагноз | Псевдоним вместо ФИО; в SMS и 1С без специализации |
| **ФИО, телефон, email**<br>C3 · хранение, передача · высокий | Самый массовый набор; при утечке — уведомление РКН за 24 ч | Шифрование полей, маскирование для ресепшена и кассы, TLS |
| **Бэкапы**<br>как у источника · хранение · высокий | Полная копия всех данных | Шифрование, отдельная площадка |
| **Согласия, договоры**<br>C3 · хранение · средний | Доказательство законности обработки | Хранилище с защитой от изменения, электронная подпись |
| **Кадровые данные, медкнижки**<br>C3 / C4 · хранение, передача в банк и ФНС · средний | ПДн сотрудников, сведения о здоровье | Отдельная база, доступ по ролям, шифрованный диск; КЭП для отчётности |
| **Платежи**<br>C2 · хранение, передача банку и ОФД · средний | Коммерческая тайна, 54-ФЗ | Шифрование, псевдоним вместо ФИО; данные карты вводятся только у банка |
| **Журнал аудита**<br>C3 · хранение · средний | Доказательства при расследовании | Только добавление записей, без изменения; доступ только у ИБ |
| **Аналитика**<br>C1 · хранение · низкий | Риск восстановить личность | Обезличивание, запрет выгрузки сырых данных |

## 2. Шифрование по состояниям

| Состояние | Как защищаем |
|---|---|
| **Хранение** | Шифрование дисков (LUKS); поля C3 / C4 шифруются отдельно ключами из Vault; шифрованные бэкапы. Удаление ключа пациента делает его данные нечитаемыми, в том числе в бэкапах |
| **Передача** | TLS 1.3 для пользователей; mTLS между сервисами; ГОСТ VPN для филиалов; mTLS + OAuth2 для лаборатории |
| **Использование** | Доступ по ролям и атрибутам, маскирование, DLP на рабочих местах |

Ключи хранятся иерархией: HSM → Vault → ключ домена → ключ пациента.

## 3. Автоматический контроль

| Что контролируем | Как |
|---|---|
| У каждого поля есть тег, C4 не уходит партнёру | Проверка в CI при каждом релизе |
| Нет незашифрованных дисков и открытых каналов | Политики Kubernetes и Terraform |
| Нет секретов и ПДн в коде и логах | Сканеры кода и логов |
| Нетипичный доступ к данным | Журнал аудита → SIEM → алерт |
| Сертификаты и ключи не просрочены | Автоматическая ротация, алерт заранее |

## 4. Реестр средств защиты

| Средство | Тип | Назначение |
|---|---|---|
| HSM | Аппаратное | Хранение мастер-ключей |
| Vault | ПО | Шифрование, токены, секреты |
| КриптоПро CSP / NGate | ПО | ГОСТ-шифрование, электронная подпись |
| ViPNet / Континент | Аппаратное | ГОСТ VPN для филиалов, межсетевой экран |
| NGFW + WAF | Программно-аппаратное | Защита периметра и портала |
| Keycloak + OPA | ПО | Вход с MFA, права доступа |
| PostgreSQL (pgaudit, Anonymizer) | ПО | Аудит и маскирование в БД |
| Secret Net Studio | ПО | Защита рабочих мест, контроль USB |
| Антивирус / EDR | ПО | Защита ПК и серверов |
| DLP (InfoWatch / Solar Dozor) | ПО | Контроль утечек |
| SIEM (MaxPatrol / Wazuh) | ПО | Мониторинг событий, алерты |
| Рутокен / JaCarta | Аппаратное | Хранение подписей, MFA |
| Облако в РФ с аттестатом УЗ-2 | Инфраструктура | Размещение системы |

Для УЗ-2 средства защиты должны быть сертифицированы ФСТЭК, средства шифрования — ФСБ.
