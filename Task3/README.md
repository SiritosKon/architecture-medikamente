# Задание 3. Шифрование данных при хранении и передаче

## 1. Классификация данных и инструменты защиты

Классы: C1 — внутренние, C2 — конфиденциальные, C3 — персональные данные, C4 — особо чувствительные (здоровье, документы, ключи).

| Данные | Класс | Риск | В чём необходимость защиты | Инструменты защиты |
|---|---|---|---|---|
| Диагнозы, анамнез, заключения | C4 | Критический | Спецкатегория ПДн и врачебная тайна (152-ФЗ ст. 10, 323-ФЗ ст. 13); утечка означает штрафы и потерю доверия | Шифрование диска и полей с ключом на пациента; доступ только лечащему врачу; TLS / mTLS |
| Результаты анализов | C4 | Критический | То же; передаются внешней лаборатории | mTLS + OAuth2, заказ без ФИО, шифрование полей |
| Паспорт, СНИЛС, полис | C4 | Высокий | Кража личности, мошенничество | Токен вместо значения, сканы не хранятся |
| Запись к специалисту, услуги в счёте | C4 (косвенно) | Высокий | По ним можно понять диагноз | Псевдоним вместо ФИО; в SMS и 1С без специализации |
| ФИО, телефон, email | C3 | Высокий | Самый массовый набор; при утечке — уведомление РКН за 24 ч | Шифрование полей, маскирование для ресепшена и кассы, TLS |
| Согласия, договоры | C3 | Средний | Доказательство законности обработки | Хранилище с защитой от изменения, электронная подпись |
| Кадровые данные, медкнижки | C3 / C4 | Средний | ПДн сотрудников, сведения о здоровье | Отдельная база, доступ по ролям, шифрованный диск |
| Платежи | C2 | Средний | Коммерческая тайна, 54-ФЗ | Шифрование, псевдоним вместо ФИО; данные карты вводятся только у банка |
| Журнал аудита | C3 | Средний | Доказательства при расследовании | Только добавление записей, без изменения; доступ только у ИБ |
| Аналитика | C1 | Низкий | Риск восстановить личность | Обезличивание, запрет выгрузки сырых данных |
| Ключи и секреты | C4 | Критический | Компрометация открывает доступ ко всему | Vault + HSM, ротация ключей |
| Бэкапы | как у источника | Высокий | Полная копия всех данных | Шифрование, отдельная площадка |

## 2. Шифрование по состояниям

| Состояние | Как защищаем |
|---|---|
| **Хранение (at rest)** | Шифрование дисков (LUKS); поля C3 / C4 шифруются отдельно ключами из Vault; шифрованные бэкапы. Удаление ключа пациента делает его данные нечитаемыми, в том числе в бэкапах |
| **Передача (in transit)** | TLS 1.3 для пользователей; mTLS между сервисами; ГОСТ VPN для филиалов; mTLS + OAuth2 для лаборатории |
| **Использование (in use)** | Доступ по ролям и атрибутам, маскирование, DLP на рабочих местах |

Ключи хранятся иерархией: HSM → Vault → ключ домена → ключ пациента.

## 3. Автоматический контроль

| Что контролируем | Как |
|---|---|
| У каждого поля есть тег, C4 не уходит партнёру | Проверка в CI при каждом релизе |
| Нет незашифрованных дисков и открытых каналов | Политики Kubernetes и Terraform |
| Нет секретов и ПДн в коде и логах | Сканеры кода и логов |
| Нетипичный доступ к данным | Журнал аудита → SIEM → алерт |
| Сертификаты и ключи не просрочены | Автоматическая ротация, алерт заранее |

## 4. Реестр средств защиты

| Средство | Тип | Назначение |
|---|---|---|
| HSM | Аппаратное | Хранение мастер-ключей |
| Vault | ПО | Шифрование, токены, секреты |
| КриптоПро CSP / NGate | ПО | ГОСТ-шифрование, электронная подпись |
| ViPNet / Континент | Аппаратное | ГОСТ VPN для филиалов, межсетевой экран |
| NGFW + WAF | Программно-аппаратное | Защита периметра и портала |
| Keycloak + OPA | ПО | Вход с MFA, права доступа |
| PostgreSQL (pgaudit, Anonymizer) | ПО | Аудит и маскирование в БД |
| Secret Net Studio | ПО | Защита рабочих мест, контроль USB |
| Антивирус / EDR | ПО | Защита ПК и серверов |
| DLP (InfoWatch / Solar Dozor) | ПО | Контроль утечек |
| SIEM (MaxPatrol / Wazuh) | ПО | Мониторинг событий, алерты |
| Рутокен / JaCarta | Аппаратное | Хранение подписей, MFA |
| Облако в РФ с аттестатом УЗ-2 | Инфраструктура | Размещение системы |

Для УЗ-2 средства защиты должны быть сертифицированы ФСТЭК, средства шифрования — ФСБ.
