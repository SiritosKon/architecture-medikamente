# Данные для защиты, тегирование, инструменты

## 1. Классы данных

| Класс | Что это | Пример |
|---|---|---|
| C0 | Публичные | Прайс, расписание филиалов |
| C1 | Внутренние | Остатки склада, агрегаты |
| C2 | Конфиденциальные | Платежи, P&L |
| C3 | Персональные данные | ФИО, телефон, адрес |
| C4 | Особо чувствительные | Диагнозы, анализы, паспорт, ключи |

## 2. Данные для защиты и способы защиты

Сейчас эти данные ни в одной системе не учтены как конфиденциальные.

| Данные | Где сейчас | Класс | Защита |
|---|---|---|---|
| ФИО, дата рождения | Excel-журнал и реестр, почта | C3 | Шифрование; ресепшен и касса видят маску `Иванов И.`; в остальных сервисах — псевдоним |
| Телефон, email | Excel, почта | C3 | Шифрование поля; маска `+7 *** **-12` |
| Адрес, место работы | Реестр, анкеты | C3 | Собирать только при необходимости; шифрование |
| Паспорт, СНИЛС, полис | Сканы на общем диске | C4 | Токен вместо значения; сканы не хранить |
| Диагнозы, анамнез, заключения | Excel-медкарты, почта | C4 | Шифрование с ключом на пациента; доступ только лечащему врачу |
| Результаты анализов | PDF, почта | C4 | Шифрование; лаборатории — псевдоним без ФИО |
| Запись к специалисту, услуги в счёте | Журнал, учёт платежей | C4 (косвенно) | Псевдоним вместо ФИО; в SMS и 1С без специализации и диагноза |
| Договоры, согласия | Сканы | C3 | Шифрованное хранилище, защита от изменения |
| Платежи | Excel + 1С | C2 | Шифрование; псевдоним вместо ФИО |
| Данные карты | POS-терминал банка | — | Не попадают в систему (оплата на стороне банка) |
| Кадры, медкнижки сотрудников | 1С, сканы | C3 / C4 | Отдельная база, доступ по ролям |
| Аналитика | Ноутбук аналитика | C1 после обработки | Обезличивание |

**Способы защиты:**
- **шифрование** — данные читаются только с ключом;
- **маскирование (обфускация)** — показывается часть значения;
- **псевдонимизация** — вместо ФИО токен, обратное сопоставление есть только внутри контура;
- **обезличивание** — необратимо, для аналитики.

## 3. Тегирование

Каждое поле получает теги:

```yaml
classification: C4          # класс
category: phi.diagnosis     # вид данных
protection: encrypt, mask   # как защищать
retention: P25Y             # срок хранения
```

| Где ставится тег | Инструмент | Что делает тег |
|---|---|---|
| Каталог данных | OpenMetadata | Единый справочник тегов и Lineage |
| База данных | PostgreSQL `SECURITY LABEL` + Anonymizer | Маскирует поле для ролей без доступа |
| API | Поле `x-data-classification` в OpenAPI | Gateway скрывает поля по правам клиента |
| Код | Аннотация `@Sensitive` | Поле не попадает в логи |

**Проверка релиза.** CI не пропускает поле без тега или поле C4 в контракте с партнёром. Результат уходит в VictoriaMetrics, при нарушении срабатывает алерт.

## 4. Инструменты по потокам

| Поток | Меры |
|---|---|
| Пациент ↔ портал | TLS 1.3, вход по OTP / ЕСИА, WAF |
| Сотрудник ↔ система | SSO + MFA, доступ по ролям и атрибутам, DLP на ПК, ГОСТ VPN для филиалов |
| Сервис ↔ сервис | mTLS, сетевые политики |
| Хранение | Шифрование диска и полей, ключи в Vault/HSM, шифрованные бэкапы |
| Лаборатория | API с mTLS + OAuth2, заказ без ФИО, договор поручения |
| Оплата | Карта вводится у банка, касса в отдельной сети |
| Согласия | Сервис согласий; отзыв останавливает обработку во всех сервисах |
| Аналитика | Обезличивание по тегам, запрет выгрузки сырых данных |
| Везде | Журнал аудита → SIEM → алерты |
